# Bug Report: Max String Recursion Exceeded in Hierarchical Exception Formatting

## Summary
When using `logger.exception()` with hierarchical formatting enabled, the colorizer hits maximum recursion depth and fails to log the exception. This occurs specifically when processing exception tracebacks through the hierarchical formatter.

## Environment
- **Loguru Version**: 0.7.3 (custom fork from https://github.com/RoscoeTheDog/loguru @ commit 66267497adad5f530d3f82025c0c4b4f1b5b2966)
- **Python Version**: 3.13.0
- **Operating System**: Windows 11
- **Framework**: Django 4.2.7

## Steps to Reproduce

### 1. Configuration
```python
from loguru import logger
from loguru._template_formatters import create_hierarchical_format_function
from loguru._exception_hook import install_exception_hook
import sys

# Remove default handler
logger.remove()

# Create hierarchical format function
console_format_func = create_hierarchical_format_function(
    format_string="{time:HH:mm:ss} | {level} | {name} | {message}",
    template="hierarchical"
)

# Add console handler with hierarchical formatting
logger.add(
    sys.stderr,
    format=console_format_func,
    colorize=True,
    level="INFO",
    backtrace=True,
    diagnose=True,
)

# Install exception hook
install_exception_hook(logger, "hierarchical")
```

## Expected Behavior
The exception should be logged with hierarchical formatting showing:
- Exception message with context fields indented
- Full traceback with IDE-clickable file links
- Exception type and value clearly displayed

## Actual Behavior
The logger fails with "Max string recursion exceeded" in the colorizer's `_parse_without_formatting` method. The exception is never logged to the console (though it does successfully log to the JSON file handler).

## Analysis

### Root Cause
The colorizer's recursive parsing of format specifications appears to enter infinite recursion when processing the complex exception traceback string generated by the hierarchical formatter.

The recursion occurs in `_colorizer.py` line 502:
```python
_, color_tokens = Colorizer._parse_without_formatting(
    format_spec, recursion_depth=recursion_depth - 1, recursive=True
)
```

This suggests the format spec being parsed contains self-referential or circular formatting that causes the parser to recurse indefinitely until hitting the max recursion depth guard.

### Affected Components
1. `loguru/_colorizer.py` - Recursion depth management
2. `loguru/_hierarchical_formatter.py` - Exception formatting output
3. `loguru/_template_formatters.py` - Format function creation

## Impact
- **Severity**: High - Breaks exception logging entirely when using hierarchical format
- **Workaround**: None for hierarchical exception logging
- **Scope**: Affects all `logger.exception()` calls with hierarchical formatting enabled

## Suggested Solutions

### Solution 1: Increase Recursion Depth Limit
**File**: `loguru/_colorizer.py`

Add a configurable maximum recursion depth or increase the current limit:
```python
# Current (line ~470)
def _parse_without_formatting(format_spec, recursion_depth=50, recursive=False):
    if recursion_depth <= 0:
        raise ValueError("Max string recursion exceeded")
    # ...

# Suggested
def _parse_without_formatting(format_spec, recursion_depth=200, recursive=False):
    if recursion_depth <= 0:
        raise ValueError("Max string recursion exceeded")
    # ...
```

**Pros**: Simple fix, minimal code change
**Cons**: Doesn't address root cause, may just delay the error

### Solution 2: Add Recursion Detection
**File**: `loguru/_colorizer.py`

Track visited format specs to detect circular references:
```python
def _parse_without_formatting(format_spec, recursion_depth=50, recursive=False, _visited=None):
    if _visited is None:
        _visited = set()

    # Check for circular reference
    if format_spec in _visited:
        return format_spec, []  # Break recursion

    _visited.add(format_spec)

    if recursion_depth <= 0:
        raise ValueError("Max string recursion exceeded")

    # ... rest of function
    # Pass _visited to recursive calls
```

**Pros**: Prevents infinite loops, maintains correctness
**Cons**: Requires careful tracking of visited specs

### Solution 3: Simplify Exception Format Output
**File**: `loguru/_hierarchical_formatter.py`

Pre-process exception traceback to remove or escape problematic format specs before passing to colorizer:
```python
def format_record(self, level, timestamp, name, message, context_fields, exception_info):
    # ... existing code ...

    if exception_info:
        # Sanitize exception output before colorizing
        exception_output = self._format_exception(exception_info)
        exception_output = self._escape_format_specs(exception_output)
        full_output += exception_output

    return Colorizer.ansify(full_output)

def _escape_format_specs(self, text):
    """Escape potentially recursive format specifications."""
    # Replace problematic patterns that cause recursion
    # Example: {foo:{bar}} -> {foo:bar}
    return re.sub(r'\{([^}]+):\{([^}]+)\}\}', r'{\1:\2}', text)
```

**Pros**: Addresses root cause, prevents recursion at source
**Cons**: May lose some formatting capabilities

### Solution 4: Separate Exception Colorization Path
**File**: `loguru/_hierarchical_formatter.py`

Create a dedicated, non-recursive colorization path for exception tracebacks:
```python
def format_record(self, level, timestamp, name, message, context_fields, exception_info):
    # ... existing code ...

    if exception_info:
        # Use simplified colorization for exceptions
        exception_output = self._format_exception(exception_info)
        exception_colored = self._colorize_exception_simple(exception_output)
        full_output += exception_colored
        return full_output  # Skip Colorizer.ansify() for exceptions

    return Colorizer.ansify(full_output)

def _colorize_exception_simple(self, exception_text):
    """Apply simple ANSI color codes without recursive parsing."""
    # Direct ANSI color application without format spec parsing
    return exception_text.replace("Traceback", "\033[31mTraceback\033[0m")  # Example
```

**Pros**: Completely avoids recursion for exceptions, maintains performance
**Cons**: Duplicates colorization logic

## Recommended Solution
**Solution 3** (Simplify Exception Format Output) combined with **Solution 2** (Add Recursion Detection) provides the best balance of:
- Fixing the immediate issue
- Preventing future recursion problems
- Maintaining existing functionality
- Minimal performance impact
